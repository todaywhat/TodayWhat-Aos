# Update Code Writing Guide

`code-writing-guide` 스킬의 팀 규칙을 **대화형 인터뷰**로 받아 분류·기록합니다.

대상 파일: `.claude/skills/code-writing-guide/` 의 `STYLE.md`, `CRITICAL.md`, `PERFORMANCE.md`

## 동작 흐름
1. 인터뷰로 규칙 구체화
2. 카테고리 분류
3. 해당 파일에 일관 형식으로 기록
4. 추가 내용 확인

## 1. 인터뷰
개발자에게 핵심만 질문해 규칙을 구체화합니다. 이미 충분히 명확하면 생략하고 진행하세요.
- **무슨 규칙인가?** (한 줄 요약)
- **왜 필요한가?** (이유·배경 — 가이드에 "why"가 있으면 모델이 규칙을 응용함)
- **좋은 예 / 나쁜 예** (가능하면 실제 코드 스니펫)
- **적용 범위** (전체 코드 / 특정 모듈·레이어)

## 2. 분류
- **STYLE**: 네이밍, 접근 제어자, 코드 구조·패턴 등 스타일 규칙
- **CRITICAL**: 위반 시 크래시·데이터 손상·하위 호환성 파손으로 이어지는 규칙
- **PERFORMANCE**: recomposition 최소화, Compose 안정성, 성능 규칙

애매하면 개발자에게 어느 카테고리인지 확인하세요.
STYLE인 경우 기존 하위 섹션(상수 네이밍 / 접근 제어자 / Route→Screen 패턴 / UI 컴포넌트 네이밍 / ViewModel 초기화 패턴) 중 알맞은 곳에 넣고, 해당하는 섹션이 없으면 새 섹션을 추가합니다.

## 3. 기록 형식
대상 파일의 알맞은 섹션 아래에 다음 형식으로 추가합니다. 형식을 일관되게 유지해야 가이드 전체가 읽기 쉬워집니다.

```markdown
### <규칙 제목>
**규칙**: <한 줄 요약>
**이유**: <왜 이렇게 하는가>
**예시**:
\`\`\`kotlin
// ❌ Bad
...
// ✅ Good
...
\`\`\`
```

이유나 예시가 불필요할 만큼 자명한 규칙이면 해당 줄은 생략해도 됩니다. 군더더기 없이 핵심만 기록하세요.

## 4. 확인
어느 파일의 어느 섹션에 무엇을 추가했는지 한두 줄로 개발자에게 보고합니다.
